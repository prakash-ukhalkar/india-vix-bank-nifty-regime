# India VIX Regime Filter for Bank Nifty Directional Prediction

A leakage-safe, dependence-aware study of whether India VIX conditions the
directional predictability of the Bank Nifty index. A two-level stacking
ensemble (XGBoost, LightGBM, Random Forest, CatBoost, and a BiLSTM with
self-attention) is trained to predict Bank Nifty direction, and the model's
reliability is evaluated separately in high- and low-volatility regimes
defined by a pre-test-fixed India VIX threshold.

## What this repository shows

Reported effects in regime-conditional financial machine learning are
frequently sensitive to two easily overlooked methodological choices: how
the regime threshold is calibrated, and how overlapping-horizon labels are
handled in significance testing. This pipeline treats both as first-class
design decisions and quantifies their impact directly:

- **Threshold calibration.** Defining "High-VIX" using the 75th percentile
  of the *test-period* VIX distribution (not knowable in real time) versus a
  threshold calibrated from **pre-test data only** changes the High-VIX
  sample from 56 days to 8 days, and changes the measured effect from
  apparently strong to statistically inconclusive — a concrete illustration
  of how much a single calibration choice can drive an apparent result.
- **Dependence in overlapping labels.** The prediction target is a 21-day-
  ahead direction label, so consecutive observations share up to 20
  overlapping future days. Naive significance testing on this kind of data
  inflates apparent significance; this pipeline instead uses a
  non-overlapping Fisher test, block bootstrap, and block-permutation test
  (see `notebooks/NB-R04`) throughout.
- **Generalizability.** A year-by-year walk-forward evaluation
  (`notebooks/NB-R05`) shows the High-VIX accuracy advantage holding in only
  one of six independently evaluated years — direct evidence that a result
  measured on a single test window can be specific to that window's
  particular stress episode rather than a general, repeatable effect.

The conclusion supported by this analysis is that the data show a
**conditional, sample-constrained pattern** worth further investigation —
not an established, generalizable regime effect or a validated trading
edge. The repository is structured so that every number behind that
conclusion is traceable to a specific, reproducible computation.

## Reproducing the analysis

```bash
git clone <repository-url> bank-nifty-vix-regime
cd bank-nifty-vix-regime
pip install -r requirements.txt
```

Then run the notebooks in `notebooks/` in numeric order (NB-R01 → NB-R13),
starting from the `notebooks/` directory. Each notebook documents its exact
inputs, outputs, and purpose in its header — see
**[`notebooks/README.md`](notebooks/README.md)** for the full pipeline map,
per-notebook dependency notes, and additional reproducibility details.

## Data

- **India VIX** (`data/raw/india_vix.csv`) and **Bank Nifty OHLCV**
  (`data/raw/market_data.csv`) are both derived from the National Stock
  Exchange of India's public historical data downloads, available for free
  in CSV format without registration.
- All engineered features are computed causally (each value at date *t*
  uses only information available up to and including *t*) — see
  `results/feature_specification.csv` for the exact formula and parameters
  of every feature.

## Method summary

- **Features:** 16 technical indicators (MACD, EMA-20, RSI-14, Stochastic
  %K/%D, ROC-10, Bollinger Bands, ATR-14, and four log-return lags).
- **Model:** a two-level stack — four Optuna-tuned tree-based learners plus
  a BiLSTM with self-attention as base learners, combined by a ridge
  logistic-regression meta-learner trained on out-of-fold probabilities.
- **Evaluation:** dependence-aware statistical testing (block bootstrap,
  block permutation, non-overlapping resampling), annual walk-forward
  validation, regime-stratified baseline comparison, SHAP-based feature
  attribution, per-component ablation, and a fully specified, deployable
  trading-rule simulation with explicit execution and risk-adjustment
  conventions.
